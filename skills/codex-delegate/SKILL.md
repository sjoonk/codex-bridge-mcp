# Codex 위임 절차

## 공통
- 툴이 오류를 내거나 처음 쓰는 세션이면 먼저 `bridge_status`를 호출해 로그인·경로 상태를 확인한다.
- 경로는 반드시 맥(호스트)의 절대경로를 쓴다. Cowork 샌드박스 경로(/sessions/...)를 넘기지 않는다.
  - 작업 폴더 매핑: bridge_status의 `workspace` 값이 Cowork에서 공유한 폴더의 호스트 경로다.

## 텍스트 작업: codex_run
1. 지시문을 자기완결적으로 쓴다: 목표, 대상 파일(호스트 경로), 원하는 출력 형식.
2. 기본은 읽기 전용. 파일 수정을 맡길 때만 `allow_write=true`.
3. 결과는 요약하고 Claude의 의견(동의/이견/보완점)을 덧붙여 보고한다. 원문은 handoff/에 자동 저장된다.
4. 후속 질문은 이전 결과의 핵심을 지시문에 포함해 다시 호출한다(세션은 이어지지 않음).

## 이미지: codex_image
1. 프롬프트를 구체적으로: 피사체, 구도, 스타일, 색감, 이미지 안 텍스트(있다면 정확한 문구).
2. 저장 위치: 프로젝트 지침에 이미지 저장 경로(호스트 절대경로)가 있으면 그 경로를 `out_dir`로 넘긴다. 없으면 생략한다(작업 폴더의 images/). 허용되지 않은 경로 오류가 나면 사용자에게 `CODEX_BRIDGE_ALLOWED_ROOTS`에 해당 폴더 추가를 안내한다.
3. 블로그 썸네일은 1536x1024, 세로 카드는 1024x1536, 아이콘은 1024x1024.
4. 생성 후 반환된 경로의 이미지를 직접 열어 확인하고, 요청과 어긋나면 프롬프트를 고쳐 최대 2회 재생성한다.
5. 한 장에 1~4분, 사용 한도 소모가 크므로 대량 생성 전에는 사용자에게 장수를 확인한다.
6. 투명 배경은 지원되지 않는다고 미리 알린다.
